# Baldwa website: notes for AI agents

## What this is
Single-page marketing site for Baldwa, an architecture and interiors studio.
Stack: Next.js 16 App Router + TypeScript, React 19, React Three Fiber 9 + drei, three.js 0.186, GSAP 3 (ScrollTrigger, @gsap/react).

## Commands
- `npm run dev` (http://localhost:3000)
- `npm run build` must pass (it also type-checks) before you finish a task.

## Rules
- Components using hooks, GSAP, R3F or browser APIs need `'use client'`. Load R3F canvases with `next/dynamic` and `ssr: false`.
- Import GSAP only from `@/lib/gsap` (plugins are registered there) and animate inside `useGSAP` with a `scope` so animations clean up.
- GSAP owns motion: do not add CSS transitions on properties GSAP animates (transform, opacity) for the same element.
- Respect reduced motion: check `prefersReducedMotion()` from `@/lib/dom` before adding animation.
- Use existing tokens (`--ink`, `--night`, `--paper`, `--surface`, `--fog`, `--gold`, `--gold-deep`, `--f-sans`). Palette (client, 2026-11-17): page background almond `#F2EDE7` (`--paper`) everywhere; light surfaces (cards, panels, pills, accents) sky grey `#B9BABD` (`--surface`, `--sky`); interactive states switch between ocean fog `#869192` (`--fog`, rest/hover) and navy `#2F4156` (`--ink`, selected/active); navy for type. Text on sky grey uses navy (`--ink`/`--ink-2`), not teal or `--gold-deep` (too faint). Accent `#F4B251` (`--gold`) only as light. No black. The logo keeps its own gold and orange. Ask before adding colours.
- The accent is too light for text on almond; use `--gold-deep` there.
- Page tone (client, 2026-11-17, after `reference videos/Screen Recording 2026-11-17 164329.mp4`): the canvas colour is `--page-bg`, scrubbed by `PageTone.tsx`: almond until Why Baldwa, blue smoke `#748795` (`--smoke`) as Brand Philosophy comes in, dark navy `#1C2836` (`--deep`) at the footer. Sections stay transparent so the change is seamless; text on the darker tones uses `html.tone-light`. The sun film lives in the footer.
- The header has no background at any scroll position. The menu is a full-screen almond overlay with the links centred.
- Colour scheme as it stands is approved: a strict five-colour recolour (gold removed, teal philosophy band, beige contact) was tried on 2026-11-17 and rejected by the client. Do not retry it.
- One typeface for everything (client, 2026-11-23): Josefin Sans (variable weight), token `--f-sans`, as a free stand-in for the client's chosen font, Athena by Ellen Luff (paid licence; switch by adding it and putting "Athena" first in `--f-sans` in `base.css`). The old font tokens are aliases of it. It is used everywhere, including the writing on the paper story. Archivo is only the wordmark inside the logo. Do not add other fonts.
- The home page reads as one continuous almond (`--paper`) canvas (client, 2026-11-17): sections have no background colour of their own and no curves, rules or edges between them. Films and the 3D stage sit inside the canvas (rounded panels, soft fades). Keep it minimal: no decorative extras.
- Keep the page single-scroll: new content is a new `<section>` component plus its own CSS file, on the shared canvas.
- Layout must work at 390px wide with no horizontal scrolling.
- three.js uses physical light units: keep intensities multiplied by `Math.PI` as in `scenes.ts`. Colours are plain sRGB hex strings (three converts them).
- Text in square brackets (e.g. `[Phone number]`) is placeholder content. Never invent real-looking contact details, client names, awards or statistics; ask the user.
- Real project photos go in `public/images/` and are referenced from `src/data/projects.ts` via `image`.

## Scroll journey
- Hero film (client, 2026-11-23, replacing `BALDWA VIDEO (1).mp4`): `HERO_FILM` in `src/lib/journey/film.ts` plays `public/videos/hero.mp4` (from `baldwa hero.webm`), scrubbed by scroll over 9 screens. It was re-encoded for scrubbing (1280 px, 30 fps, keyframe every 10 frames, no audio, faststart) with the generator marks in the bottom-right corner (the "Veo" label, and a sparkle in the last half-second) filled in with ffmpeg `removelogo` (mask: 56 x 54 px box at 1162,604 and 46 x 32 px at 1230,684 in the 1280 x 720 frame); re-encode any replacement the same way. Full length: don't trim the end (client, 2026-11-23); the last half-second (a sheet of paper appears on the desk, a hand reaches for the hard hat) leads into the paper story. `public/images/hero-poster.jpg` is its first frame. Cloud opening (client, 2026-11-23, "cloud dispersal on scroll like before"): the photo clouds (`cloud-deck.webp`, `cloud-bank.webp`, warm-graded by `.film-sky`) cover the first frame and part on scroll, and the film's first 3 s are spread over the first 20% of scroll (`HERO_CLOUDS` in `film.ts`). The white fade at the bottom of the hero was removed on request; don't add it back. This machine has no ffmpeg on PATH; CapCut's `ffmpeg.exe` (no libx264, so `h264_nvenc`) was used. Setting `HERO_FILM` to null brings back the two-clip film below.
- Right now the opening is the film version: `USE_FILM` in `Journey.tsx` scrubs two client clips (`src/lib/journey/film.ts`: segments, clip times, the drone move, the dissolve between the clips), staged after `reference videos/sky.mp4`: hero title over clouds, fast dive through them, one continuous drone glide. Setting it to false brings back the real-time 3D journey below, which is kept intact.
- One number drives it: `journey.p` (0 to 1), written only by the ScrollTrigger in `Journey.tsx`. The 3D world, the camera and the HTML overlays read it. Keep every state a pure function of `p` (no accumulated state), so scrolling back restores it.
- To add a stage: add it to `BUILT` in `stages.ts` with a length in screens, add camera keys with `at('stage', t)`, add its objects to the shared root in `world.ts` and set their state inside `update(p)`. Remove it from `PLANNED`.
- One hotel model must serve the blueprint, construction, finished and tabletop stages; build it once and vary materials and visibility by `p`.
- World units are metres; the plot centre is the origin and `+z` points to the road. Use `PLOT` and `ROAD` from `stages.ts`.
- Text and navigation stay in HTML (`CHAPTERS` in `stages.ts`). Reduced motion gets the still image; no WebGL gets the 2D reveal.
- No paid generators, paid APIs or generated video. Procedural geometry, shaders and freely licensed local assets only; record every downloaded asset in `ASSETS.md`.

## Paper story (after the hero)
- Client, 2026-11-23: `PaperStory.tsx` (section right after `Journey`) is the bridge from the hero film to the featured projects. From the film's last frame: the sheet (sticker on it from the start, bottom right) lifts to the centre while the hero photo slides up half a screen over a plain cream lower half; the heading (the studio name, `BRAND.name`) and then the four services (PMC & Construction Management, BIM Engineering, Architecture, Interior Consultancy; client, 2026-11-23) are written while everything holds still; then three things happen together: the hero is released and scrolls up, the sheet rolls up on it and leaves with it, and the Projects heading and panels slide in from the right, purely sideways, at their final height (Projects is already pinned at the top behind the hero). Nothing overlaps: the projects only come on screen where the hero and the sheet have already cleared (`projectsSlide`). Projects then works exactly as before. The heading and services are `title` and `points` in `src/lib/paper/config.ts`.
- How it fits together: one sticky stage (one screen tall, z 2) holds the hero photo, a cream panel under it (`.ps-panel`, slid up by script inside the stage, hidden once the hero is released) and the paper canvas; it stays pinned through the stages in `config.stages`, then scrolls away. Projects sits behind the stage's last screen (`.paper-story + .work`: margin -100vh, z 1, top edge plain cream) so it is at the top of the screen, pinned, when the hero is released. `--pj-lead: 1` there makes `Projects.tsx` start its accordion one screen later (its track is one screen taller to match), so the accordion and its wheel handling are unchanged. Projects only ever moves by normal scrolling: don't move it vertically with a transform (an earlier version did, and it jittered on every scroll because the browser scrolls a frame ahead of the script).
- Curl: spiral roll in `paperRoll.ts` (uRoll 0..1, radius growing per turn, slight taper), the sheet leans back and turns a little while rolling so the tube is seen in perspective, cylinder shading and a sheen line on the tube, a contact shadow where it sits on the sheet, darker inner turns, a plain back (only a trace of ink showing through), and a soft drop shadow of the floating sheet on the page behind it (`drop` in config.ts). The sheet is forced fully opaque past its alpha test (the paper PNG is slightly see-through). Paper: the client's blank sheet (`paper.webp`, made neutral), tinted in the shader (`light.tint`) so it renders as the Projects background colour (--cream #F6EEE1) and blends in; heading and points in the site font with a faint pencil rule under each; centred sheet 82% of the screen height.
- Every tweakable value (stage lengths, start pose, shadow, lamp tint, roll radius, texts, layout) is in `src/lib/paper/config.ts`. `timeline.ts` maps progress to state (pure, like `journey.p`), `texture.ts` draws the paper face (photo + writing + stickers on one canvas, so they roll with it), `src/lib/three/paperRoll.ts` is the bend/roll vertex shader on a MeshStandardMaterial, `src/lib/three/paperScene.ts` the plain three.js scene, rendered on demand.
- Handoff: the section starts two screens early under the hero (`.journey--live + .paper-story`, margin -200vh) and stays invisible until the film reaches its last frame, then crossfades to `public/images/paper/table-frame.jpg`: the film's last shown frame (23.5 s, marks removed) with the film's sheet of paper patched out from the 22.95 s frame. (Extra static sheets baked onto the table were tried and removed on request, 2026-11-23.) The 3D sheet's start pose (`start` in config.ts) is fitted to that sheet's four corners, so it takes its place. If the hero film changes, rebuild the still and re-fit the pose. The background is CSS (object-fit: cover, like the video); its blur is a pre-blurred copy faded in, cheap on phones.
- Debug panel (lil-gui): press D on localhost, or anywhere with `?debug`. "Copy values" logs the start pose / shadow / roll / lamp as JSON for config.ts.
- Fallbacks: no WebGL gets the HTML paper sliding and writing (no curl); reduced motion gets one still screen with all points written. The points are real text in the DOM in every version (screen-reader copy in the WebGL one).
- Lenis was asked for in the brief but not added: it would take over scrolling on the whole page and fight the one-project-per-gesture wheel handling in `Projects.tsx`. The section uses native scroll and a ScrollTrigger progress like the rest of the page.

## Interactive villa
- Opens in Evening light (client, 2026-11-24).
- The section now shows the 3D floor plan built from the client's rendered plan image, staged after `reference videos/WhatsApp Video 2026-11-16 at 5.10.20 PM.mp4`: `src/data/floorplan.ts` (walls, furniture, rooms traced in image pixels), `src/lib/three/planModel.ts` (the image is the floor; furniture is raised and textured from it), `src/components/three/PlanScene.tsx` (lights, camera, opening sequence), `VillaPlan.tsx` (controls). The notes below describe the earlier sample model (`villa.ts`, `villaModel.ts`, `VillaScene.tsx`), which is no longer shown but still in the repo.
- Rooms are rectangles in feet on a 60 × 44 ft grid, north at z = 0. Walls are generated between rooms in `villaModel.ts`; door openings come from `doors` in `villa.ts`.
- Furniture is chosen by room `kind` in `furnish()` in `villaModel.ts`; add a `case` for a new kind.
- Room floor slabs are R3F meshes in `VillaScene.tsx` (hover/click); camera targets live in the shared `Controls` ref.
